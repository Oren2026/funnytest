# v0.2 — Ollama gemma4 整合版

日期：2026-05-07

## 版本目標

實作 Ollama gemma4 控制器整合，建立工具介面系統與 Workspace 持久化機制。

v0.2 的核心是**讓 gemma4 可以操控 Evolution Engine**，透過工具呼叫（Tool Use）介面達成。

#### 2. 工具介面系統

gemma4 可呼叫的工具：

| 工具名 | 參數 | 回傳 | 說明 |
|--------|------|------|------|
| `diverge` | node_id, content, count | Vec\<Node\> | 從指定節點發散生成多個子節點 |
| `converge` | - | ConvergeResult | 觸發收斂，移除低分節點 |
| `save` | name | SaveResult | 儲存目前狀態到 workspace |
| `load` | name | LoadResult | 從 workspace 載入指定狀態 |
| `output` | format ("xml" \| "md") | OutputResult | 產出 XML 或 MD 檔案 |
| `status` | - | StatusResult | 回傳狀態摘要 |

**工具執行器**：
```rust
// src/tools/executor.rs
struct ToolExecutor {
    graph: Arc<Mutex<Graph>>,
    workspace: Workspace,
}

impl ToolExecutor {
    fn execute(&self, tool_call: ToolCall) -> ToolResult
    fn execute_diverge(&self, node_id: &str, content: Option<Vec<String>>, count: i32) -> ToolResult
    fn execute_converge(&self) -> ToolResult
    fn execute_save(&self, name: &str) -> ToolResult
    fn execute_load(&self, name: &str) -> ToolResult
    fn execute_output(&self, format: &str) -> ToolResult
    fn execute_status(&self) -> ToolResult
}
```

#### 3. Workspace 系統

**位置**：`~/Desktop/funnytest/evolution_reasoning/workspace/`

**狀態同步方式**：Evolution Engine 將狀態寫入 workspace/*.xml，gemma4 自己讀取。

**目錄結構**：
```
workspace/
├── status.xml          # 目前狀態摘要（gemma4 讀這個）
├── state.xml           # 完整圖狀態
├── session_001.xml     # 已命名的儲存點
└── output/
    └── graph.md         # 輸出格式（可選）
```

**狀態 XML 格式**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<evolution_state>
  <meta>
    <version>0.2</version>
    <saved_at>2026-05-07T02:00:00Z</saved_at>
    <name>session_001</name>
  </meta>
  <complexity>
    <current>23.5</current>
    <max>100</max>
    <k>1.0</k>
  </complexity>
  <nodes>
    <node id="uuid-1" step="1" weight="0.8" confidence="0.7" status="active">
      <content>節點內容</content>
    </node>
  </nodes>
  <edges>
    <edge id="e1" from="uuid-1" to="uuid-2" type="reasoning" weight="0.5"/>
  </edges>
</evolution_state>
```

**Status XML 格式**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<evolution_status>
  <meta>
    <version>0.2</version>
    <mode>diverging</mode>
  </meta>
  <graph>
    <node_count>5</node_count>
    <edge_count>4</edge_count>
    <complexity>23.5</complexity>
    <max_complexity>100.0</max_complexity>
  </graph>
  <active_nodes>
    <node id="uuid-1" step="1" content="節點內容" weight="0.8" confidence="0.7"/>
  </active_nodes>
</evolution_status>
```

**Workspace API**：

#### 4. Gemma Controller

**職責**：管理 gemma4 的對話狀態、系統提示詞、與工具執行器的整合。

```rust
// src/controller/gemma_controller.rs
enum ControllerMode {
    Diverging,   // 發散模式（預設）
    Converging,  // 收斂模式
    Mixed,       // 混合模式
}

struct GemmaController {
    ollama_client: OllamaClient,
    tool_executor: Arc<ToolExecutor>,
    mode: ControllerMode,
    current_task: Option<String>,
}

impl GemmaController {
    fn new(ollama_url: &str, model: &str) -> Self
    fn set_task(&mut self, task: &str)
    fn set_mode(&mut self, mode: ControllerMode)
    fn build_system_prompt(&self) -> String
    fn build_messages(&self, user_input: &str) -> Vec<Message>
    
    // 處理 gemma4 的回應，執行工具呼叫
    async fn process_response(&self, response: ChatResponse) -> Result<Vec<ToolResult>>
    
    // 主要對話迴圈
    async fn run(&self, task: &str) -> Result<()>
}
```

**系統提示詞框架**：
```
你是一個推理控制器。

當前任務：{task}
狀態摘要：讀取 workspace/status.xml
當前模式：發散（默認）

約束條件：{constraints}

可用工具：
- diverge(node_id, content, count)
- converge()
- save(name)
- load(name)
- output(format: "xml" | "md")
- status()

規則：
- 默認模式為發散
- 當複雜度 > 閾值，自動提醒
- 沒有固定目標，持續探索
- 產出存到 workspace/
```

## 備註

v0.2 的重心是**工具系統**和**狀態持久化**。

gemma4 作為控制器，透過工具介面操控 Evolution Engine。狀態同步透過 Workspace XML 檔案達成，gemma4 自己讀取 status.xml 來取得狀態摘要。

這個版本不要求完美的整合，但要求系統可以運作，這樣才有東西可以觀察和討論。
